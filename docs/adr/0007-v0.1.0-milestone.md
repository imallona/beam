# 0007 - v0.1.0 milestone: schema, seed registry, and CI

- Status: Accepted
- Date: 2025-03-01
- Deciders: Izaskun Mallona
- Supersedes: -
- Superseded by: -

## Context

v0.1.0 is the foundation the later work builds on: the JSON Schema for metric cards, two or more real cards, and a CI gate that rejects malformed contributions. The decision module cannot be wired into the cards until the schema exists.

## Decision

v0.1.0 contains:

1. `schema/metric_card.schema.json` (draft 2020-12), with the minimum fields needed to describe a metric: identity, kind (derived or measured), inputs and output, semantics (scale, polarity, range, allowed transformations, uncertainty), comparability, implementations, examples, and provenance. Conditional rules: derived metrics must have `inputs`; metrics with `requires_ground_truth: true` must declare the ground truth.
2. Two real cards: `metrics/ari/v1.yaml` (derived, interval scale, requires ground truth) and `metrics/runtime/v1.yaml` (measured, ratio scale, no ground truth). These two cover opposite ends of the schema.
3. `tests/test_schema.py` for Python-side validation. Parametrised over every discovered card. Also checks that the id matches the directory and the version matches the filename.
4. `tests/validate_cards.R` for R-side validation via `jsonvalidate`, run in a separate CI job.
5. GitHub Actions workflow: ruff lint, ruff format check, pytest on Python 3.12 and 3.13, R-side validation.
6. Packaging: `pyproject.toml`, hatchling backend, src/ layout.
7. `CONTRIBUTING.md`, `CHANGELOG.md`, `metrics/LICENSE.md` (CC-BY-4.0).

## Consequences

Positive: - The schema is the contract the decision module will bind to. - R-side validation in CI from day one stops the schema drifting toward Python-only semantics. - The two seed cards are real, not toy, and unblock the Duo 2018 vignette. - Every later contribution passes the CI gate, so the registry stays consistent with no manual review.

Negative: - No runtime functionality ships in v0.1.0. The project is not yet usable end to end. That is fine for a foundation release.

## Alternatives considered

- Ship the decision module first (lift the notebook code) without the schema: rejected. The result would still hand-type a profit_cost_vector, the exact failure mode beam is designed to eliminate.
- Skip R-side validation initially and add it later: rejected. Dual-language consistency is a design constraint (ADR 0002), and retrofitting cross-language validation is harder than enforcing it from the start.
